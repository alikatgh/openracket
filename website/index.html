OpenRacket

An experimental project to update DrRacket’s interface while retaining its existing editor and tools.

Status: development preview. Full stock compatibility, native platform behavior, and performance are still being checked. There is no finished application release offered here.

Source

The repository contains two approaches. Their setup instructions and feature coverage differ.

  • Retained DrRacket experiment — current work on the prototype/retained-drracket branch. It uses the original DrRacket 9.3 GUI host, editors, tool callbacks, and evaluator.
  • Earlier Rust editor preview — the application source on main. It uses Iced and a separate Racket process. It is not a complete DrRacket replacement.

Retained-host implementation

The current experiment applies presentation changes to DrRacket rather than replacing its editor implementation:

  • A version-pinned patch changes the stock toolbar button painting and spacing.
  • An appearance tool provides experimental color, font, editor-margin, focus, and status-row adjustments.
  • The original editor objects, registered tool callbacks, and evaluation machinery remain in use.

Keeping the host does not by itself establish compatibility. Native menus, dialogs, tool windows, rich documents, and language-specific workflows need separate verification.

Rust preview build instructions

Code execution: running a Racket program executes local code with your account’s privileges. Process separation is not a security sandbox. Use trusted programs when testing.

Validation and limitations

  • Full equivalence with stock DrRacket has not been established. Component tests and a successful window launch do not verify every workflow.
  • Native acceptance includes Linux and macOS behavior, including tool integration, input, focus, clipboard, dialogs, and display scaling. See the current acceptance notes and test runs for results.
  • The earlier Rust preview has documented gaps in debugging, teaching tools, macro stepping, rich documents, and DrRacket integration.
  • Performance comparisons must use the same hardware, settings, instrumentation, and workloads. No speed multiplier is claimed.

Fresh-profile capacity, 2026-10-11: new isolated profiles now default to a 256 MiB per-job limit, preserving existing profiles and explicit settings. The tested 1 MiB analysis completed in 3/3 trials at 256 MiB, while stock 128 MiB ran out of memory in 3/3. The Mac installer and eight-launch acceptance run passed. Completion still took about 33–39 seconds and total peak RSS was about 1.5 GB; this is a capacity fix, not an editor speedup. Evidence and limits.

Earlier autosave result, 2026-10-11: three matched Mac replacement-autosave pairs for a 1 MiB fixture reduced command medians from 266.735 to 172.400 ms (35.4% between arm medians), with exact recovery checks passing. Actual Mac installation and combined save/recovery gates also passed in a later run whose independent expansion-replay preparation failed. Initial lexer-validity waits were about 34–40 seconds; combined performance has not been retimed. Changelog and evidence · Measurement details and limits.
