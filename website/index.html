02 / The idea

Keep the substance.
Refine the surface.

DrRacket is more than an editor. OpenRacket’s direction is to modernize the experience while keeping the machinery that makes it useful.

01

Familiar by design

The same two-pane rhythm. The same places to look for Run, Check Syntax, Debug, and Macro Stepper. A modern appearance should build on your muscle memory.

02

Depth worth preserving

The current experiment retains DrRacket 9.3’s own host, editors, and tool callbacks. Stock functionality is the goal; native workflow checks are how we earn that claim.

03

Faster, with evidence

Responsiveness matters. The plan is to measure complete workflows, identify bottlenecks, and improve them without dropping tools, instrumentation, or behavior.

Development preview

This is an evolving project. Here’s what you’ll find in the repository, and what still needs to be established.

  1. Explore now

    The source and the experiment

    The main branch holds the earlier Rust editor preview. A separate retained-host branch explores modernizing the original DrRacket environment.

    Retained-host branch ↗

  2. Validation work

    The complete workflow

    Native Linux and macOS behavior, stock tools, rich documents, and platform integration need direct testing before full compatibility can be claimed.

    Acceptance criteria ↗

  3. Measurement work

    Performance that holds up

    Compare startup, editing, analysis, and tool workflows on the same system with the same settings. No speed multiplier is claimed.

    Measurement approach ↗
Can I download a finished app?+

OpenRacket is a source-level development preview. There is no finished, supported application release offered here. The repository documents the earlier Rust preview, while the retained-host branch has its own experimental setup instructions.

Read the repository guide ↗
Is this a complete DrRacket replacement?+

Not yet. Full stock functionality is the goal. The current direction keeps DrRacket’s own host and tools rather than recreating each feature, but that architecture still needs end-to-end native verification. The earlier Rust preview has documented feature gaps.

How can I help?+

Explore the source, read the known limitations, and share a reproducible issue with your platform, Racket version, and the steps you tried. Useful areas include native behavior, accessibility, tool compatibility, and repeatable performance measurements.
